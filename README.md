# eval-assistant — 경량 LLM 평가용 한국어 질문지 생성 + E2E 검수 도우미

날씨·로컬·금융 도메인의 한국 특화 평가 질문을 자동 생성하고,
카나나 샌드박스 앱 검수(복사 → 붙여넣기 → 응답 기록)를 한 화면에서 처리한 뒤
카카오 제출용 xlsx까지 추출하는 로컬 도구입니다.

**핵심 설계**: LLM은 한국 지식을 몰라도 됩니다. 지명·종목·금융용어는 시드 데이터(`seeds.yaml`)가
주입하고, LLM(Qwen3 등)은 자연스러운 한국어 문장화만 담당합니다. LLM이 없어도 템플릿 모드로 동작합니다.
검수를 통과한 질문은 자동으로 few-shot 예시로 재사용되어 **쓸수록 체감되는 생성 품질이 올라갑니다.**

## 설치 — WSL/Ubuntu 기준

### 1. Python 환경

```bash
sudo apt update
sudo apt install -y python3-venv python3-pip

cd ~/Development/eval-assistant
python3 -m venv .venv                 # 가상환경 생성 (최초 1회)
source .venv/bin/activate             # 활성화 — 새 터미널을 열 때마다 실행
pip install -r requirements.txt
```

> **왜 venv?** 우분투 최신 버전은 시스템 파이썬에 pip 설치를 막습니다
> (`externally-managed-environment` 에러). venv를 쓰면 이 문제가 없고,
> `--break-system-packages`나 pip 전역 설정 변경 없이 깔끔하게 관리됩니다.

### 2. Ollama (LLM 모드용 — 선택)

```bash
sudo apt install -y zstd                          # 설치 스크립트가 요구함
curl -fsSL https://ollama.com/install.sh | sh     # 공식 설치 (snap 사용 금지: 구버전)
systemctl status ollama                           # active(running) 확인. 아니면: ollama serve
ollama pull qwen3:4b                              # 약 2.5GB
```

Ollama가 없으면 자동으로 템플릿 모드로 동작합니다(문장 다양성은 낮지만 흐름 동일).

### 자주 걸리는 문제

| 증상 | 해결 |
|---|---|
| `Command 'pip' not found` | 위 1번의 `apt install python3-venv python3-pip` |
| `externally-managed-environment` | venv 활성화(`source .venv/bin/activate`) 후 pip 실행 |
| Ollama 설치 중 `requires zstd` | `sudo apt install zstd` 후 재시도 |
| `gio: ... Operation not supported` | 무해함. WSL엔 브라우저가 없어서 자동 열기 실패 — Windows 브라우저에서 직접 접속 |
| 첫 실행 시 이메일 입력 프롬프트 | 그냥 Enter. 이 저장소의 `.streamlit/config.toml`이 이후엔 안 뜨게 함 |
| 코드를 고쳤는데 반영이 안 되는 것 같음 | **다른 인스턴스가 8501을 점유** 중일 수 있음(예: 윈도우 run.bat 서버 + WSL 서버 — WSL2는 localhost를 공유). 사이드바의 '데이터 위치'로 어느 쪽에 접속했는지 확인하고, 한쪽을 끄거나 포트를 분리(`--server.port 8502`) |

## 동료 PC 배포 — 윈도우 네이티브, 방문 설치 15분

개발 PC(WSL)와 달리 동료 PC에는 윈도우 네이티브로 설치한다. 인터넷은 설치 단계에서만 필요하다.

1. **Python 3.10+ 설치** — python.org 공식 설치기, **"Add python.exe to PATH" 반드시 체크**.
   (설치 전에도 `python` 명령이 있는 것처럼 보일 수 있으나 스토어 스텁임 — setup.bat이 감지해서 알려줌)
2. **Ollama 설치** — OllamaSetup.exe 실행. 선택 사항 — 없으면 템플릿 모드로 동작.
3. **코드 폴더 복사** — 단, `.venv`(리눅스용이라 무용)와 `data/`(원본 검수 데이터가 따라감)는
   빼고 복사. 새 검수자는 빈 data로 시작해야 한다.
4. **`setup.bat` 더블클릭 1회** — venv 생성 → 패키지 설치 → qwen3:4b 다운로드(약 2.5GB) →
   바탕화면 "E2E-Assistant" 바로가기 생성.
5. **일상 사용 = 바탕화면 E2E-Assistant 더블클릭 1회** — 서버가 최소화 창으로 뜨고 준비되면
   브라우저가 자동으로 열린다. 종료는 최소화된 "E2E Assistant server" 창 닫기.
   이미 실행 중일 때 다시 더블클릭하면 브라우저만 다시 열린다.

## 사용법

### 검수 도우미 (권장)

```bash
source .venv/bin/activate
streamlit run app.py
```

Windows 브라우저에서 `http://localhost:8501` 접속.

1. **① 질문 생성** — 도메인·개수·배치 크기 선택 후 생성. 로컬 SQLite(`data/eval_assistant.db`)에 저장.
   과거 생성분과 완전/준중복되는 질문은 자동으로 걸러진다.
   **생성은 백그라운드로 진행**된다 — 페이지를 이동하거나 ②에서 검수를 계속해도 끊기지
   않고, 질문은 만들어지는 즉시 저장되며 진행률은 사이드바에 표시된다.
   같은 탭의 "질문 정리"에서 검수 전에 별로인 질문을 일괄 **결함 제외**(기록 남음)하거나
   **영구 삭제**(흔적 없음), 또는 **선택만 남기고 나머지 삭제**할 수 있다.
   먼저 검수하고 싶은 질문은 "먼저 검수"로 대기열 맨 앞에 보낸다(건너뜀·제외 상태도 복원됨).
   정리 표는 실제 검수 순서로 정렬되고 대기 건에 순번이 붙어, 우선 지정 효과가 바로 보인다.
2. **② 검수 진행** — 기본은 대기열 맨 앞 질문이지만, 상단 드롭다운에 키워드를 입력해
   (예: "바비") **원하는 질문을 검색·선택해 바로 검수**할 수 있다. 검수를 마치면 자동으로
   원래 순서로 복귀. "묶어서 검수"로 인텐트를 고르면(예: 금융/시세 조회) 그 인텐트의
   질문만 순서대로 이어져 저장할 때마다 같은 유형의 다음 질문이 자동으로 나온다 —
   대기열의 저장 순서는 바뀌지 않으며, 묶음이 소진되면 전체 대기열로 복귀. 질문 박스의 복사 버튼 → 카나나 앱에 붙여넣기 → 응답 전문 붙여넣기 후
   **E2E 품질평가 양식 그대로 2축 판정**: 1) 정확도(pass/fail + N 사유 + 코멘트),
   2) LLM 출력(pass/fail + 오류 유형 + 코멘트). search ID도 함께 기록.
   질문 자체가 이상하면 "질문 결함 → 제외" (생성 품질 개선 신호로 쓰임).
   조금만 고치면 쓸 수 있는 질문은 "질문 다듬기"로 수정 — 고친 질문이 검수를 통과하면
   few-shot 예시가 되므로, 버리는 것보다 좋은 예시를 하나 더 공급하는 효과가 있다
   (필수 엔티티 유지·중복 검사 적용. 단, 모델이 '수정 전→후' 패턴을 학습하는 건 아니다).
   테스트 중 직접 떠올린 질문은 "직접 떠올린 질문 추가"에 먼저 등록 — 과거에 비슷한
   질문을 이미 검수했는지 경고해 주고, 저장 즉시 다음 검수 차례가 되며, 검수를 통과하면
   few-shot 예시로 재사용된다(사람이 쓴 질문이라 생성 개선 신호 중 가장 강함).
   **입력 실수 방지**: 앱 응답·search ID는 필수이고(응답을 받으면 반드시 함께 생성되므로),
   이전 검수 기록과 똑같은 search ID/응답을 붙여넣으면 저장 전에 경고한다.
   직전 저장이 실수였다면 "방금 저장한 검수 되돌리기"로 즉시 재검수 대기로 되돌린다.
3. **③ 결과·내보내기** — 정확도/LLM 출력 pass율 집계, xlsx 다운로드.
   검수 결과 표가 **카카오 제출양식과 같은 컬럼 순서**로 나와 셀을 드래그 선택해
   그대로 복사·붙여넣기하면 된다. 여러 명이 하나의 공유 시트에 붙여넣는 운용이면
   **표시 범위 필터(오늘 검수분/날짜 지정)**로 그날 분량만 띄워 복사한다. 양식에 열이 추가·삭제되면 "컬럼 구성 수정"에서
   줄 단위로 맞춘다(줄 삭제 = 컬럼 제거, 데이터에 없는 이름 = 제목만 있는 빈 컬럼).
   xlsx의 '제출양식' 시트도 이 구성을 따르고, '내부분석' 시트에 앱 응답 전문 등이 남는다.
   "검수 기록 수정·삭제"에서 완료 건을 골라 오타·잘못 붙여넣은 값을 고치거나(검수일시·
   테스터는 원본 유지), 재검수 대기로 되돌리거나, 질문째 영구 삭제할 수 있다 —
   sqlite를 직접 다룰 필요 없음.
4. **④ 트렌드 시드** — 최신 기사·리뷰 본문을 붙여넣으면 로컬 LLM이 시드 후보(유행 품목·
   지역·종목 등)를 추출하고, 체크박스로 검토해 등록한다(광고 문구·기자명은 추출·검토
   단계에서 걸러짐). 등록된 시드는 ① 탭의 **주입 비율**만큼 생성에 섞이고 유효기간이
   지나면 자동 제외된다. 트렌드 시드가 쓰인 질문은 `시드출처=trend`로 태깅되어
   ③ 탭에서 **최신성 fail율을 기본 시드와 비교**할 수 있다 — 카나나가 최신 정보를
   못 따라오는 지점을 정량적으로 보여주는 지표.
   `typhoon_name`(태풍 이름)·`ipo_stock`(공모주)·`hot_item`(유행 품목)은 **트렌드 전용
   풀**이라, 시드를 등록하면 태풍 경로·공모주 청약·유행 아이템 구매처 같은 **이벤트형
   인텐트가 자동 활성화**되고 시드가 만료되면 다시 비활성화된다.

| 포트 | 서비스 | 용도 | 변경 방법 |
|---|---|---|---|
| 11434 | Ollama API | 앱 ↔ 모델 내부 통신 | `OLLAMA_HOST` 환경변수 / `generate.py --host` |

## 생성 속도가 느릴 때

CPU 추론에서 병목은 토큰 생성이 아니라 **호출마다 반복되는 프롬프트 처리(prefill)** 입니다.
이 도구는 다음이 기본 적용되어 있습니다:

- **배치 생성**: 호출 1회당 8개(조절 가능) 생성 → 고정 프롬프트 비용을 8분의 1로
- **keep_alive 30분**: 호출 간 모델 재로딩 방지 (첫 호출만 로딩 때문에 유독 느린 게 정상)
- **num_predict 상한**: 출력 폭주 방지

추가로 시도할 수 있는 것:

- **더 작은 모델**: `qwen3:1.7b` — 문장화만 하는 이 태스크에선 품질 하락이 작고 약 2배 빠름.
  모델 태그만 바꿔서 몇 배치 뽑아 비교해볼 것
- **WSL 자원 늘리기**: Windows의 `C:\Users\<이름>\.wslconfig`에
  `[wsl2]` `memory=12GB` `processors=8` 지정 후 PowerShell에서 `wsl --shutdown`.
  WSL 기본값은 호스트 RAM의 절반이라 CPU 추론 성능에 직접 영향
- **대량 생성은 걸어두기**: 대화형이 아니므로 점심/퇴근 전에 `generate.py`로 수백 건 걸어두는 운용이 합리적

## 품질 관리 체계

생성 질문은 저장 전에 자동 검증을 통과해야 합니다: 엔티티 포함 여부, 길이,
**외국어 혼입(한자·가나·비고유명사 로마자)**, 완전/준중복. 탈락하면 재시도 후 템플릿 폴백.
중복 방지는 두 겹입니다. **문자 검사**(trigram 유사도)는 DB(앱)·출력 JSONL(CLI)에 쌓인
과거 질문 전체와 비교하지만, 짧은 문장에서는 조사 하나만 달라도 통과하므로 거의 동일한
문구만 잡습니다. 그래서 "같은 것을 문구만 바꿔 또 묻는" 중복은 **(인텐트, 엔티티) 조합
회피**가 담당합니다 — 이미 다룬 조합(이번 실행 + 과거 누적)은 피해서 샘플링하고, 해당
도메인의 조합 공간이 소진됐을 때만 반복을 허용합니다.

여기에 사람 피드백 루프가 겹쳐집니다: 검수자가 "질문 결함 → 제외"로 표시한 질문은 few-shot에서
배제되고, **검수를 통과한 실제 질문이 few-shot 예시로 자동 재사용**(도메인별 안배 샘플링)되므로
검수가 쌓일수록 모델이 좋은 예시를 보고 생성하게 됩니다. **직접 떠올려 추가한 질문**도 검수를
통과하면 같은 풀에 들어가는데, 모델 자기 출력이 아닌 사람의 문형이라 반향실 효과를 깨는 가장
좋은 예시가 됩니다. 단, 이 루프는 검수자가 결함 질문을 성실히 "제외"할 때만 작동하는 개연적
개선 장치이지 자동 보장이 아닙니다.

## 최신성 반영 원칙 (트렌드 시드)

최신성은 LLM이 아니라 **시드 데이터의 신선도** 문제입니다. 기사 원문을 프롬프트에 넣거나(사실
각인·prefill 비용·광고 혼입 위험) 모델을 학습시키는(불필요·과적합 위험) 대신, 기사에서
**엔티티만 추출해 유효기간 있는 트렌드 풀**로 편입합니다. 가중치 학습이 없으므로 잘못된
시드가 들어가도 영향은 해당 배치에 국한되고, 시드 삭제 + 질문 정리로 완전히 되돌릴 수 있습니다.
주제 쏠림은 주입 비율 상한·유효기간·실행 간 준중복 방지가 막습니다. 자동 스크래핑은 붙이지
않습니다. 저작권·약관 문제에 더해 "유일한 네트워크 호출은 Ollama뿐"이라는 보안 원칙이
깨지기 때문입니다. 복사-붙여넣기 + 사람 검토가 기본 흐름입니다.

## 도메인·시드 확장하기

- **인텐트 추가**: `taxonomy.yaml`의 해당 도메인에 `id/name/slots/templates` 블록 추가.
- **새 슬롯**: `seeds.yaml`에 같은 이름의 풀을 추가. `{include: [풀A, 풀B]}`로 합성 풀 가능.
- **이벤트형 인텐트**: 풀을 `[]`(빈 리스트)로 두면 트렌드 전용이 된다 — ④ 탭에서 그 풀에
  시드가 등록된 동안에만 해당 인텐트가 생성 후보에 들어간다. 새 풀을 ④ 탭 추출 대상에
  넣으려면 `app.py`의 `TREND_POOL_GUIDE`에 설명 한 줄을 추가.
- **주의**: 인텐트와 슬롯 풀의 의미가 맞아야 함. 예: "계산" 인텐트에 `신용점수`가 들어가면
  비문이 생성됨 → 금융은 `fin_condition_term`/`fin_pay_term`/`fin_calc_term`처럼 용도별 풀 사용.
- **시드 갱신**: 종목명(KRX)·행정구역은 변동됨. 갱신 시 파일 상단 스냅샷 날짜도 수정.

## 데이터·보안 유의사항

- 모든 데이터(생성 질문, **카나나 앱 응답 전문**, 판정)는 이 PC의 `data/` 폴더에만 저장.
  유일한 네트워크 호출은 `localhost:11434`(Ollama)뿐.
- `.streamlit/config.toml`이 UI를 localhost로 제한함 — 기본값(0.0.0.0)이면 같은 네트워크의
  다른 PC에서 검수 데이터에 접근 가능하므로 이 설정을 지우지 말 것.
- 카나나 앱 응답은 고객사(카카오) 검수 데이터에 해당할 수 있음. `data/` 폴더와 추출 xlsx를
  개인 클라우드·외부 메신저로 옮기지 말고 사내 규정에 따른 경로로만 공유.

## 알려진 한계 / 다음 단계

- '기획 검수' 컬럼은 카카오 측 기입란으로 보고 제목만 있는 빈 컬럼으로 표시·내보냄.
  양식이 바뀌면(열 추가·삭제) ③ 탭의 "컬럼 구성 수정"에서 줄 단위로 맞춤 —
  줄을 지우면 컬럼 삭제, 데이터에 없는 이름(예: 비고)을 적으면 빈 컬럼 추가.
- 대시보드(추이·검수자별 현황·필터)는 2차 범위. `db.py`를 그대로 재사용해 붙일 수 있음.
- 트렌드 시드는 앱 전용 (CLI `generate.py`는 DB를 읽지 않으므로 기본 시드만 사용).
- 템플릿 모드는 문형 다양성이 제한적 → 다양성이 필요한 배치는 LLM 모드 권장.
